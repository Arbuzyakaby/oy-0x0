## История в двух абзацах

**OY** начиналась как французский стартап бывших спасателей из Канады. Первый телефон, **OY 0X0**, вышел в конце 2027 года под девизом «Ноль слежки. Ноль компромиссов.»: четыре аппаратных выключателя, шторка на камере, сигнальный фонарь на 5000 метров и ни одного облачного сервиса. За ним пришли линейки 0X1 и 0X2, раскладушки Moth и флагман Nova. У OY появился собственный процессор Argon.

Потом в OY сменился CEO: пришёл человек из Xiaomi. С ним появились OY ID, облако 0X Cloud и встроенные сервисы Google. Основатели и инженеры по одному уходили в Стокгольм, в **Fyr**. «Fyr» по-шведски значит «маяк». Там они выпустили часы **Osmium X0** и ноутбук **KBook 1**. Сначала Fyr «взламывала» этот сайт через пасхалку в подвале. Теперь сайт принадлежит ей.

## Пасхалка «Перехват»

Раньше Fyr заходила на сайт через подвал. Этот вход оставлен на память.

1. Откройте любую страницу OY и пролистайте до подвала.
2. Наберите на клавиатуре `x0` (подойдёт и `ч0`). На телефоне вместо этого пять раз подряд нажмите на щит в подвале.
3. Картинка сорвётся, текст закроют чёрные полосы, и сайт перекрасится в чёрный, синий и белый. Фразы OY сменятся ответами Fyr, цены станут шестнадцатеричными.
4. Режим держится до закрытия вкладки и переходит на другие страницы. Кнопка «Вернуть OY» слева внизу всё отменяет.

Код живёт в `js/fyr/`: `hijack.js` — загрузчик и триггеры, `glitch.js` — сцена и откат, `dict.js` — словарь замен.

## Запуск

Сайт — это обычные HTML, CSS и ES-модули. Нужен только локальный веб-сервер, потому что по `file://` браузер не загружает GLB-модели.

```bash
git clone https://github.com/Arbuzyakaby/oy-0x0.git
cd oy-0x0
python -m http.server 5317
```

Откройте `http://localhost:5317`. Подойдёт и любой другой статический сервер, например `npx serve .`. В Claude Code превью-сервер описан в `.claude/launch.json` под именем `oy`.

Параметры адреса:

| Параметр | Что делает |
|---|---|
| `?fallback` | Показывает процедурную модель вместо GLB, как при ошибке загрузки |
| `?debug` | Открывает в консоли состояние 3D-сцены и ScrollTrigger (на страницах, где это предусмотрено) |

### Данные — в одном месте

Цены, конфигурации памяти, цвета и вся таблица сравнения лежат в `js/data/products.js`. Конфигураторы, главная, мини-сравнение и страница `/compare/` берут цифры только оттуда. Цены указаны в долларах и евро.

### Прокрутка и сцены

GSAP ScrollTrigger управляет сценами, а Lenis делает прокрутку плавной. Позы 3D-моделей заданы ключевыми кадрами, привязанными к главам страницы (`js/core/keys.js`). Между кадрами модель плавно интерполируется. Рендер ставится на паузу, когда сцену не видно или вкладка скрыта.

### Без сборщика

Зависимости грузятся с `cdn.jsdelivr.net` через import map, который вписан в каждую страницу. Собственные модули подключаются по путям вида `/js/...`. Скрипт `tools/stamp.mjs` дописывает к ним версии.

## 3D-модели

- Каждая модель собирается скриптом `blender/build_*.py`, общие материалы и примитивы — в `blender/oy_common.py`. Рендеры аксессуаров делает `build_accessories.py`, они попадают в `img/accessories/`.
- На сайте модель показывает `js/core/stage.js`, а `js/models/<устройство>.js` её загружает и рисует экраны на canvas (циферблат часов, рабочий стол CamelOS, экран Nova).
- Если GLB не загрузился, остаётся процедурная модель того же устройства. Страница не ломается.

## Как добавить устройство

1. Опишите модель в `js/data/products.js`: цены, память, цвета. Добавьте колонку в `COMPARE_MODELS` и значения во все строки `COMPARE`.
2. Соберите модель в Blender (`blender/build_<id>.py`) и положите GLB в `models/`.
3. Напишите `js/models/<id>.js` и сценарий `js/pages/<id>.js`.
4. Сделайте страницу `<id>/index.html` с шапкой, подвалом, плашкой переходного периода и щитом «Перехвата».
5. Добавьте модель на главную, в шапку всех страниц и при необходимости в аксессуары.
6. Выполните `npm run stamp`, затем `npm test`.

## Тесты

```bash
npm test
```

Сначала проверяется, что версии файлов актуальны. Затем запускаются юнит-тесты:

| Файл | Что проверяет |
|---|---|
| `products.test.js` | Цены, цвета, лестницу цен, преемников снятых моделей, наценку за мрамор, совпадение сравнения с данными; что юаней и eXtream в данных нет |
| `pages.test.js` | Import map и подключённые файлы, шапку и подвалы, главы страниц и якоря, плашку переходного периода, страницы Fyr и хронику, запрещённые слова; что ни юаней, ни eXtream на сайте нет |
| `fyr.test.js` | Словарь «Перехвата», hex-цены, триггеры `x0` и пять касаний |
| `keys.test.js` | Ключевые кадры поз |

Сценарии из `tests/e2e/` запускаются через Playwright MCP (`browser_run_code_unsafe { filename }`) на `http://127.0.0.1:5317`. Они проходят страницы на десктопе и телефоне, проверяют демо и снимают скриншоты в `docs/screenshots/`.

## Выкладка

Хостинг кеширует JS и CSS на несколько часов. Поэтому перед выкладкой обязательно выполните:

```bash
npm run stamp
```

Скрипт дописывает к CSS, скриптам и GLB параметр `?v=` с хешем содержимого и пересобирает import map каждой страницы. Если хоть одна версия устарела, `npm test` упадёт.

## Приватность

- Нет аналитики, трекеров, cookies и сторонних виджетов.
- Сторонний источник один — `cdn.jsdelivr.net` (Three.js, GSAP, Lenis). Шрифты лежат на самом сайте.
- На каждой странице стоит Content Security Policy.
- В `localStorage` хранятся только мелочи: выбранный цвет, валюта, созвездия на странице Nova. Режим «Перехвата» живёт в `sessionStorage` до закрытия вкладки.

Проверьте сами во вкладке «Сеть» в DevTools.

## Доступность и скорость

- Семантическая разметка, подписи к иконкам, видимый фокус, контраст не ниже AA.
- Все демо и переключатели работают с клавиатуры.
- При `prefers-reduced-motion` нет закреплённых сцен и плавной прокрутки: всё сразу показывается в конечном виде.
- `devicePixelRatio` ограничен двумя, 3D рисуется только на экране.
- Вёрстка рассчитана на экраны от 360 px.
