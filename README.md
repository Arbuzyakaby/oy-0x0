# Fyr · телефоны OY

Демонстрационный сайт о двух вымышленных компаниях. Телефоны делала **OY**, а **Fyr** основали её бывшие инженеры в Стокгольме. Теперь сайт принадлежит Fyr. Идёт переходный период: на главной стоят часы и ноутбук Fyr, а телефоны пока продаются под маркой OY.

Всё на сайте выдумано: компании, устройства, цены, события. Купить здесь ничего нельзя, и посещения сайт не считает.

Адрес: [oy0x.online](https://oy0x.online)

## Сюжет коротко

OY начиналась как французский стартап бывших спасателей. Первый телефон, 0X0, вышел под девизом «Ноль слежки. Ноль компромиссов.». Со временем у компании сменился CEO, пришедший из Xiaomi. Вместе с ним в OY появились аккаунт, облако и встроенные сервисы Google. Основатели и инженеры по одному уходили в Fyr.

Потом случилось вот что:

1. Французская полиция арестовала CEO OY.
2. Антимонопольный орган Франции разделил OY на две компании: **XNA** для Северной Америки и **OY Europe** для Европы.
3. Китайская часть, **XZF**, ещё до раздела незаконно отделилась и продалась Huawei.
4. XNA передала OY Europe поддержку американских телефонов, а сама занялась облаком. 0X Cloud и 83 дата-центра в США остались у неё, и пользователям нужно забрать оттуда свои данные.
5. OY Europe обанкротилась. Около 70 % её сотрудников перешли в Fyr.
6. Инженеры Fyr выбросили в Манхэттенский залив ключ от бэкдора, которым OY управляла чипами безопасности в телефонах.
7. На фоне всего этого OY 0X2 Pro впервые в истории бренда стал самым продаваемым смартфоном в Евросоюзе. Раньше OY была первой в Европе только среди раскладушек, с Moth 2.
8. Fyr обещает скоро выпустить OY OS 5 и вернуть тот самый дух старой OY.

Целиком эта история рассказана на странице [`/fyr/chronicle/`](https://oy0x.online/fyr/chronicle/).

## Пасхалка

Раньше Fyr попадала на сайт «через подвал». Мы оставили этот вход на память. Доскролльте до подвала любой страницы OY и наберите на клавиатуре `x0` (или `ч0`). На телефоне вместо этого пять раз подряд нажмите на щит в подвале. Сайт помехами перейдёт в цвета Fyr, фразы OY сменятся ответами Fyr, а цены станут шестнадцатеричными. Режим держится до закрытия вкладки. Кнопка «Вернуть OY» всё отменяет.

## Запуск

Собирать ничего не надо: сайт состоит из обычных HTML, CSS и ES-модулей. Нужен только локальный веб-сервер, потому что по `file://` браузер не отдаёт GLB-модели.

```bash
git clone https://github.com/Arbuzyakaby/oy-0x0.git
cd oy-0x0
python -m http.server 5317
```

Затем откройте `http://localhost:5317`. Подойдёт любой статический сервер, например `npx serve .`.

Параметры адреса:

- `?fallback` — показать запасную процедурную модель вместо GLB;
- `?debug` — вывести состояние 3D-сцены в консоль (на страницах, где это предусмотрено).

## Выкладка

Хостинг кеширует JS и CSS на несколько часов. Поэтому перед каждой выкладкой выполните:

```bash
npm run stamp
```

Скрипт `tools/stamp.mjs` дописывает к CSS, скриптам и GLB параметр `?v=` с хешем содержимого. Внутренние импорты модулей он подменяет через import map каждой страницы. Если хоть одна версия устарела, `npm test` упадёт.

## Устройство

```
index.html, */index.html   страницы; шапка и подвал вписаны в каждую
css/                       core.css — общее, остальное — по странице
js/core/                   3D-сцена, прокрутка, ключевые кадры, текст, интерфейс
js/models/                 загрузка GLB и процедурные модели-заглушки
js/pages/                  скрипт каждой страницы
js/data/                   цены, цвета и сравнение — единый источник
js/fyr/                    пасхалка «Перехват»: загрузчик, сцена, словарь
models/                    GLB, собранные в Blender
blender/                   скрипты сборки моделей (build_*.py)
tools/stamp.mjs            версии файлов для кеша
tests/unit/                node --test
tests/e2e/                 сценарии Playwright со скриншотами
docs/superpowers/specs/    спецификации страниц и сюжетных поворотов
```

Как работают страницы:

- **3D.** Модели собраны скриптами в `blender/`, на сайте их показывает Three.js (`js/core/stage.js`). Если GLB не загрузился, остаётся процедурная модель того же устройства. Рендер стоит на паузе, пока сцену не видно.
- **Прокрутка.** GSAP ScrollTrigger управляет сценами, а Lenis делает прокрутку плавной. Позы моделей задаются ключевыми кадрами, привязанными к главам страницы (`js/core/keys.js`).
- **Данные.** Цены, цвета, сравнение и список моделей в продаже лежат в `js/data/products.js`. Витрина и страница сравнения берут их оттуда.
- **Хроника.** Карту мира рисует сам скрипт (`js/pages/fyr-chronicle.js`): точки по сетке 72×25 без картинок. Ключ падает в залив по прокрутке.

## Приватность

- Нет аналитики, трекеров, cookies и сторонних виджетов.
- Сторонний источник один — `cdn.jsdelivr.net`, откуда приходят Three.js, GSAP и Lenis. Шрифты лежат на самом сайте.
- На каждой странице стоит Content Security Policy.
- В `localStorage` хранятся только мелочи вроде выбранного цвета, валюты и созвездий на странице Nova. Режим пасхалки живёт в `sessionStorage` до закрытия вкладки.

## Доступность

- Все демо и переключатели работают с клавиатуры, фокус виден.
- При `prefers-reduced-motion` нет закреплённых сцен и плавной прокрутки: всё сразу показывается в конечном виде.
- Вёрстка рассчитана на экраны от 360 px.

## Тесты

```bash
npm test
```

Сначала проверяются версии файлов, затем юнит-тесты:

- `pages.test.js` — import map и подключённые файлы, шапки, плашка переходного периода, страницы Fyr и хроника, запрещённые слова;
- `products.test.js` — цены, цвета и сравнение;
- `fyr.test.js` — словарь и триггеры пасхалки;
- `keys.test.js` — ключевые кадры.

Сценарии из `tests/e2e/` запускаются через Playwright MCP (`browser_run_code_unsafe`) на `http://127.0.0.1:5317`. Они проходят страницы и снимают скриншоты для `docs/screenshots/`.
